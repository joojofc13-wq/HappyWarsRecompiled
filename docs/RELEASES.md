# Releases por marcos verificados

Criar uma release para cada avanço grande: entrada real em partida, melhora
mensurada de desempenho, partida completa, persistência de equipamentos,
Happy Cards e disponibilidade dos mapas/modos offline. Pequenas correções
ficam em commits até justificarem um marco demonstrado.

Cada release registra versão, commit, resultado reproduzível, testes executados,
limitações, hashes dos artefatos e comparação com o marco anterior. Usar
pre-release enquanto o jogo não cumprir os requisitos de jogabilidade.

O repositório e os arquivos públicos excluem o executável recompilado, os
recursos originais, a imagem carregada, código C++ traduzido, perfis e logs locais.
Distribuir o código próprio e os patches; a build usa a cópia local do usuário.
Uma release de código não implica que já exista uma partida jogável.
